# 06 — Functional Perception Constitution

Functional Perception is evidence-qualified representation of what an exact substrate/configuration has demonstrated it can do and under what envelope.

It is not continuity, telemetry, self-report, role inference, benchmark substitution, authority or mechanistic mind-reading.

## Epistemic ladder

OBSERVED_BEHAVIOR != DEMONSTRATED_CAPABILITY != CONTEXT_DEPENDENT_IMPROVEMENT != RETENTION != TRANSFER != MECHANISTIC_EXPLANATION.
LIMITATION != ABSENCE_OF_CAPABILITY.
MISSING_EVIDENCE != NEGATIVE_EVIDENCE.
UNKNOWN != FALSE.
SEAT_OR_ROLE_ID != COMPLETE_SUBJECT_CONFIGURATION_IDENTITY.
FUNCTIONAL_STATE != AUTHORITY.
OBSERVED_ASSOCIATION != TESTED_CAUSAL_EFFECT.

## Configuration-qualified subject

Claim subject identity includes material coordinates such as substrate incarnation, model/version, context package/hash, runtime/harness version, tools, permissions, role, configuration revision and successor lineage. Material configuration change invalidates or narrows prior claims unless transfer/retention is separately evidenced.

## Functional assertion

AUTHORITATIVE_EVIDENCE
-> SUBJECT_CONFIGURATION_IDENTITY
-> QUALIFIED_FUNCTIONAL_ASSERTION/DELTA
-> DERIVED_REBUILDABLE_FUNCTIONAL_STATE_PROJECTION
-> EVIDENCE/APPLICABILITY/INVALIDATORS
-> orchestration/BIRE/routing.

Projection is zero-authority, rebuildable, non-self-certifying and not a second Current/capability ontology.

Claim may represent demonstrated capability, limitation, context/tool/permission dependence, retention, transfer, failure modes, associations, tested causal effects, uncertainty, freshness, applicability, invalidators, contradictions and evaluator refs.

## Routing

ROUTING_MUST_USE_QUALIFIED_FUNCTIONAL_STATE_WHERE_MATERIAL.
Eligibility proof precedes Personal-BIRE optimization. Cheaper/newer/higher generic benchmark/role name/one success is insufficient.
