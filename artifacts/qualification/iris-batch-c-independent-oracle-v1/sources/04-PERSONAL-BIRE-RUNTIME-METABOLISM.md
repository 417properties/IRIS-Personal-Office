# 04 — Personal BIRE Runtime Metabolism / Mode Arbitration

Personal BIRE is the resource/outcome lens across time, attention, energy, cognitive load, money/capital, relationship capital, optionality, friction, risk and opportunity cost.

## Runtime rule

CHEAPEST_SUFFICIENT_CONFIG_THAT_PRESERVES_REQUIRED_CAPABILITY, never merely cheapest available.

Mode is execution configuration, not identity/personality/authority.

Modes:
conversational/social-presence; ambient/low-latency voice; triage/attention; research; deep analysis; decision preparation; orchestration/worker management; deterministic/tool execution; verification/reconciliation; learning/recalibration; cold reconstruction/continuity.

Non-collapse:
MODE != IRIS_IDENTITY.
MODE != PERSONALITY.
MODEL != MODE.
MODE != AUTHORITY.
LOWER_COST != LOWER_REQUIRED_CAPABILITY.
RESOURCE_OPTIMIZATION != SEMANTIC_DEGRADATION.
VOICE_SESSION != IRIS_CURRENT.
BACKGROUND_WORKER_STATE != IRIS_CURRENT.

## Arbitration inputs

Objective/consequence class; required capability floor; reasoning depth; latency; evidence/coverage; privacy; authority sensitivity; context/reconstruction burden; modality; tools/workers; duration/concurrency; provider availability/reliability; token/API/compute/storage/network cost; Aaron attention/energy burden; opportunity cost; expected value; reversibility; fallback/degradation.

Eligibility comes before ranking. Functional Perception/qualification determines which configurations are eligible. Personal BIRE then selects among eligible configurations.

## Dual-layer Personal Office

Foreground: responsive interaction, stable referent/personality, immediate minimum-sufficient reasoning, only necessary interruption.
Background: durable objectives/obligations, deeper research/analysis, bounded workers, reconciliation, decision/action preparation, effect verification and durable state independent of live chat.

Foreground/background concurrency never creates two Currents or duplicate continuation ownership.
